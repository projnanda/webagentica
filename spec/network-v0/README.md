# network.v0 machine contracts

The normative text is [`../network-v0.md`](../network-v0.md). This folder holds what a runtime
implements against and what `scripts/verify_network.py` validates:

| File | What it is |
|---|---|
| `workflow.schema.patch.json` | RFC 6902: `workflow.schema.json` gains the top-level `network` object (§2.1: `entry`, `max_hops`, `state_schema`, `initial`, `message_schema`, `result`, `roles`), the `role` and `route` definitions (§2.2, §2.5), the value source `message` (§2.5), and on nodes the `network` type with its conditionals (§2.1). Applied to agentpkg's live schema by T25; the Chrome copy is synced from it. |

The route's output schema is built by the runtime from the declaration (§4, R-13), so there is
no contract file for it. The enforcement cases (§7) are listed in
[`examples/network/cases/cases.json`](../../examples/network/cases/cases.json) and built by the
probe `agentpkg/tests/network_probe.py`; the test package and the travel example are under
[`examples/network/`](../../examples/network/), generated by `make_network_examples.py`.

Run the check from the repository root:

```sh
agentpkg/.venv/bin/python scripts/verify_network.py
```

It prints a JSON report with `"passed"`, and exits 1 on any failure.
